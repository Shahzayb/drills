  The conflict table this walks a corner of (Postgres docs, "Explicit
  Locking"). ACCESS EXCLUSIVE is the only mode that conflicts with
  ACCESS SHARE, which is the mode a plain SELECT takes — which is why it
  is the only one that can stop a read:

    ACCESS SHARE             SELECT
    ROW EXCLUSIVE            INSERT / UPDATE / DELETE
    SHARE                    CREATE INDEX          blocks writes, not reads
    SHARE UPDATE EXCLUSIVE   VACUUM, ANALYZE, VALIDATE CONSTRAINT,
                             CREATE INDEX CONCURRENTLY   blocks neither
    ACCESS EXCLUSIVE         ALTER TABLE, DROP, TRUNCATE   blocks everything
